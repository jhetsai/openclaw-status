# 2026-07-10 ESP32-S3-Touch-LCD-4.3B 時鐘維修日誌

## 問題描述
**時鐘秒數落後現實時間約 3 秒**：每 3 秒 real time 時鐘才跳 1 秒，且 WiFi 連線後時間會亂跳。

---

## 維修過程

### 1. 發現：Timer 本身是 1Hz，但畫面更新落後

開機 log 顯示：
```
[TIMER] fire interval=1000000 us  ← 正確 1Hz
[CLOCK] tick=8 base=0 OK         ← 每 3.2 秒才出現一次（不是每秒）
```

**根本原因：** `esp_timer_start_periodic(timer, 1000000)` 參數是對的，但 timer 触发後的 `lvgl_port_lock(1000)` 在 fetch 期間要等 3 秒才能拿到 lock，導致 `clock_pending_` 被設了但一直沒機會處理。

### 2. 第一階段修復：strftime 移到 lock 外

```cpp
// 修復前：strftime 在 lock 內，佔用 lock 太久
if (lvgl_port_lock(1000)) {
    strftime(disp_buf, ...);    // ❌ 慢，佔 lock
    lv_label_set_text(...);
    lvgl_port_unlock();
}

// 修復後：strftime 在 lock 外，lock 只做 set_text
strftime(disp_buf, ...);        // ✅ 先格式化
if (lvgl_port_lock(1000)) {
    lv_label_set_text(...);     // ✅ 極快
    lvgl_port_unlock();
}
```

**結果：** CLOCK log 變成每秒出現，但畫面仍落後 3 秒。確認問題是 `lv_label_set_text()` 雖然更新了 LVGL 內部 buffer，但 **LCD flush 延遲**仍約 3 秒。

### 3. 第二階段修復：改用 LVGL lv_timer

放棄 `esp_timer` + `lvgl_port_lock` 模式，直接用 **LVGL 自己的 lv_timer**（自帶 lock-safe，在 LVGL task 內執行）：

```cpp
lv_timer_create(
    [](lv_timer_t *) {
        auto *a = app_ptr;
        a->clock_seconds_++;
        if (a->ui_ready_ && a->home_clock_lbl_) {
            time_t now = (a->clock_base_time_ > 1000000000L)
                ? a->clock_base_time_ + a->clock_seconds_
                : time(nullptr);  // NTP 還沒 sync，先用系統時間
            struct tm ti;
            localtime_r(&now, &ti);
            char buf[32];
            strftime(buf, sizeof(buf), "%m/%d %H:%M:%S", &ti);
            lv_label_set_text(a->home_clock_lbl_, buf);  // 直接呼叫，不用 lock
        }
        // 每 10 秒用 time() 當 fallback（NTP 可能還沒 sync）
        if (a->clock_seconds_ % 10 == 0 && a->clock_base_time_ == 0) {
            time_t now = time(nullptr);
            if (now > 1000000000L) {
                a->clock_base_time_ = now;
                a->clock_seconds_ = 0;
            }
        }
    },
    1000,  // 1Hz
    nullptr);
```

**結果：** 時鐘精準每秒更新，畫面不再落後。

### 4. 第三階段：SNTP 延遲導致 clock_base_time_=0

有時 WiFi 連線慢，SNTP 還沒 sync，`clock_base_time_` 一直是 0。改善方式：

```cpp
time_t now = (a->clock_base_time_ > 1000000000L)
    ? a->clock_base_time_ + a->clock_seconds_
    : time(nullptr);  // Fallback：直接用系統時間
```

每 10 秒檢查一次，如果 `clock_base_time_==0` 且 `time()` 已有合理值（> 2001-09-09），就採用 `time()` 當基準。

### 5. wifi_just_connected_ flag 的移除

原本在 WiFi callback 設 `sntp_needed_=true` 並在 LvglTask 處理，會造成：
- WiFi callback 觸發 → 網路 fetch 開始
- SNTP init 延後到此時才執行
- `clock_base_time_` 被錯誤設定（網路時間還沒取到）

修復：SNTP 在 Initialize() 就直接 init，不等 WiFi callback：

```cpp
setenv("TZ", "CST-8", 1);
tzset();
esp_sntp_config_t sntp_cfg = ESP_NETIF_SNTP_DEFAULT_CONFIG_MULTIPLE(
    2, ESP_SNTP_SERVER_LIST("tw.pool.ntp.org", "time.google.com"));
sntp_cfg.wait_for_sync = false;
esp_netif_sntp_init(&sntp_cfg);
```

### 6. WiFi RSSI fetch 修復（同時處理的）

原本 RSSI fetch 在 WiFi callback（sys_evt stack，太小），TLS 握手會爆。
修復：WiFi callback 只設 flag，在 LvglTask（stack 8KB）fetch RSSI：

```cpp
board.SetNetworkEventCallback([this](NetworkEvent event, const std::string &data) {
    if (event == NetworkEvent::Connected) {
        this->wifi_connected_ = true;
        this->wifi_just_connected_ = true;  // 只設 flag
    }
});

// LvglTask 裡處理
if (app->wifi_just_connected_) {
    app->wifi_just_connected_ = false;
    wifi_ap_record_t ap;
    esp_wifi_sta_get_ap_info(&ap);  // ✅ 在大 stack 執行
    app->wifi_rssi_ = ap.rssi;
    lv_label_set_text(app->home_wifi_lbl_, ...);
}
```

## 最終架構

### Timer 架構
| 用途 | 方法 | 優點 |
|------|------|------|
| 時鐘（1Hz） | `lv_timer_create()` | 自帶 lock-safe，不需搶 LVGL lock |
| 資料更新（1分鐘）| `esp_timer_start_periodic()` | 可以独立运行，不阻塞 UI |

### 時鐘公式
```cpp
time_t now = (clock_base_time_ > 1000000000L)
    ? clock_base_time_ + clock_seconds_
    : time(nullptr);  // Fallback
```

### WiFi RSSI 更新時序
```
WiFi Connected → wifi_just_connected_=true → LvglTask fetch RSSI → 更新 UI
```

## 已知問題（未解決）

1. **USB 燒錄後 ESP32 不會自動重置** — 需要手動按 RST
2. **deep sleep mode** — 有時燒錄後 USB 斷開，需要按 RST 喚醒
3. **ESP32-S3 內建溫度感測器不相容** — 只能用天氣 API 溫度
