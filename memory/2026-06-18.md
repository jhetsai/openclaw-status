## 記憶索引 ETL 優化（2026-06-18）

### 問題：記憶體不足（舊版 etl_memory.py）
- 一次讀取所有 .md 檔案到記憶體
- 模型持續占用 ~1GB
- 導致 OOM 被 Kill，執行失敗

### 解法：etl_memory_v3.py 極致輕量版
1. **逐檔處理**：不用 list，一次只讀取一個檔案
2. **每 3 檔 GC**：每處理 3 個檔案強制 `gc.collect(1)`
3. **EMBED_BATCH = 3**：每批只 encode 3 個 chunk 即寫入 DB 並釋放
4. **延遲載入模型**：第一個檔案需要才 load model，之後留在記憶體重複用
5. **每次刪除大型物件後立即 gc.collect()**

### 成效
- 236 個檔案 → 3,896 chunks
- 記憶體穩定在 **968MB**（未超過 1GB）
- 耗時約 **13 分鐘**，完整跑完無崩潰

### 結論
下次執行記憶索引 ETL，**使用 `scripts/pgvector/etl_memory_v3.py`**，不再使用舊版 etl_memory.py
