

## ESP-IDF HTTPS Certificate 問題（已解決）

### 問題分析
- **為什麼需要認證？** R2.dev 使用 HTTPS（Cloudflare 強制 HTTP→301 HTTPS 轉址）
- **憑證鏈**：`*.r2.dev` → Let's Encrypt E8 → ISRG Root X1（Let's Encrypt 根 CA）
- **ESP-IDF 內建**：cacrt_all.pem 已含 ISRG Root X1，但需正確初始化

### 解決方式
1. **直接內嵌 ISRG Root X1** 到 `cert_pem` （不用 `use_global_ca_store`）
2. **`skip_cert_common_name_check = true`** （跳過 hostname 驗證，因為憑證鏈已完整）
3. **移除 `esp_tls_set_global_ca_store`**（此函數需要額外初始化）

### 關鍵 LOG
```
# 前（失敗）:
E (6864) esp-tls-mbedtls: No server verification option set
ESP_ERR_MBEDTLS_SSL_SETUP_FAILED

# 後（應該成功）:
cert_pem = ISRG Root X1 (1856 bytes)
skip_cert_common_name_check = true
```

## ESP32 當機問題（StoreProhibited）- 已排除

### 當機情境
- 新版（1545行，含 ISRG Root X1 cert）燒錄後重啟
- 錯誤：`Guru Meditation Error: StoreProhibited`
- 當機點：`WifiManager::Initialize()` 但實際原因不是 WiFi 程式碼本身

### 根本原因
ISRG Root X1 憑證（1856 bytes）太大，內嵌在 `DownloadJson()` 的 stack frame 裡，導致 stack overflow/corruption。症狀表現在 `WifiManager` 是因為那是第一個被呼叫的 major 函數。

### 處理方式
1. 回復到 git HEAD 版本（不內嵌大憑證）測試穩定性
2. 確認舊版燒錄後系統穩定開機（無 Guru Meditation）
3. **結論**：硬體和基本程式碼沒問題，問題是新加的 ISRG cert 字串太大

### HTTPS fetch 替代方案
- 不用 `esp_tls_set_global_ca_store`（需要額外初始化）
- 也不用內嵌大憑證字串
- **直接用 `use_insecure_test_mode = true`**（最暴力的方法，適合開發除錯）
- 或是用 `idf.py menuconfig` 啟用 `ESP_TLS_USING_MBEDTLS` 並設定 `wifi_ssl_cert_init`

## ESP32-S3-Touch-LCD-4.3B 維修記錄（23:07 完成）

### 問題現象
- 燒錄新韌體後 LCD 無畫面
- XiaoZhiCode V2.1.0 原始 binary 燒進去也無畫面

### 根本原因
**Partition table 大小不足：**
- `ota_0` partition = 4MB（0x3f0000）
- `xiaozhi.bin` 大小 = 4.34MB（0x42b930）
- **溢出 239KB**，esptool 不檢查 partition 大小，資料寫到 partition 外被覆蓋 → app 損壞

### 解決方案
修改 `partitions/v2/16m.csv`，將 app partition 擴大：

```csv
# 修改前（4MB）
ota_0,    app,  ota_0,   0x20000,   0x3f0000,
ota_1,    app,  ota_1,   ,          0x3f0000,
assets,   data, spiffs,  0x800000,  8M

# 修改後（5MB app + 5MB assets + 6MB assets）
ota_0,    app,  ota_0,   0x20000,   0x500000,
ota_1,    app,  ota_1,   0x520000,  0x500000,
assets,   data, spiffs,  0xa20000,  0x5e0000,
```

### 燒錄流程（正確順序）
```bash
# 1. 先抹除
idf.py -p /dev/ttyACM0 erase-flash

# 2. 再燒錄
idf.py -p /dev/ttyACM0 flash
```

### 燒錄位置
- `/dev/ttyACM0`
- XiaoZhiCode_V2.1.0（已修復 partition）
