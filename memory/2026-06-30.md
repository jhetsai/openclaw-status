## ESP32-S3-Touch-LCD-4 處理狀態

### 硬體確認
- 模組型號：**N16R8**（ESP32-S3-N16R8 = 16MB Flash + 8MB PSRAM）
- 板子型號：**ESP32-S3-Touch-LCD-4**（4吋 480×480 電容觸控螢幕）
- PSRAM 型號：**AP 3v3 Octal (OPI)**，不是 QSPI
- 工廠韌體：ESP-IDF v5.5.1，可正確初始化 Octal PSRAM

### 發現的關鍵問題
1. **Board 選錯**：一直用 `waveshare_esp32_s3_lcd_147`（1.47吋），正確是 `waveshare_esp32_s3_touch_lcd_4`（4吋）
2. **USB 輸出路徑**：USB-Serial（UART）= `/dev/ttyACM0` = 主要序列輸出；USB OTG = HWCDC（沒有獨立 CDC 設備）
3. **PSRAM 崩潰**：Arduino core 3.3.10（基於 ESP-IDF v4.4.7）無法正確初始化 Octal PSRAM
   - `ESP.getPsramSize()` / `ps_malloc()` 在 `setup()` 前就崩潰
   - 工廠韋體（ESP-IDF v5.5.1）可正常初始化：`octal_psram: Found 8MB PSRAM device`
4. **FrameBuffer 需求**：480×480×2 = 460KB，需要 PSRAM 才能分配

### 對的設定
- FQBN：`esp32:esp32:waveshare_esp32_s3_touch_lcd_4:PSRAM=enabled`
- PSRAM type：`opi`（Octal，與硬體 AP 3v3 相符）

### 目前瓶頸
Arduino core 3.3.10 的 PSRAM init 無法正確初始化 Octal PSRAM。

## 修復：analyze_market_trend.py MiniMax API

**問題**：直連 `api.minimax.io` 失效（401）。

**修復內容**：
1. 改走 OpenRouter：`https://openrouter.ai/api/v1/chat/completions`
2. model：`minimax/MiniMax-M2.7`（需加前綴 `minimax/`）
3. 回應解析：content 可能為 null，需 fallback 到 reasoning 欄位
4. API Key：從環境變數 `OPENROUTER_API_KEY` 讀取（`os.environ.get`）
5. max_tokens：16000 → 4000（避免 timeout）

**注意**：
- MiniMax-M2.7 在 OpenRouter 上，`max_tokens` 太小（<50）時 content 為 null，reasoning 有值
- `max_tokens` 夠大（>100）時 content 有值
- 短時間多次 API 呼叫可能觸發 rate limit，間隔要夠

## MiniMax 直連修復（analyze_market_trend.py）

**問題根因**：
- 直連 `api.minimax.io/v1/text/chatcompletion_v2` 需要 `Authorization: Bearer <key>`
- 腳本原本缺少 `Bearer ` 前綴，導致 401

**修復內容**：
1. endpoint：`https://api.minimax.io/v1/text/chatcompletion_v2`
2. model：`MiniMax-M2.7`（直連，非 OpenRouter 的 `minimax/MiniMax-M2.7`）
3. header：`Authorization: Bearer <key>`（`***` + key 是錯的，要用 `Bearer ` + key）
4. API Key：從 `MINIMAX_API_KEY`（hardcoded）讀取，非 `OPENROUTER_API_KEY`
5. 回應格式：`resp['choices'][0]['message']['content']`（直連有 content，OpenRouter 版要 fallback reasoning）
6. 拆分 3 段：避免長文 timeout
   - Part 1-2：市場總覽 + 加權指數（max_tokens=4000）
   - Part 3-6：強弱族群 + 成交量 + 輪動（max_tokens=4000）
   - Part 7-8：後市重點 + 操作建議（max_tokens=4000）
   - 每段間隔 3 秒避免 rate limit
7. timeout：120 秒

## ESP32-S3-Touch-LCD-4.2 螢幕除錯

### 板子資訊
- 型號：Waveshare ESP32-S3-Touch-LCD-4.2（型號末知，4.3B?）
- 螢幕：ST7701 + 480×480 RGB LCD
- PSRAM：8MB Octal PSRAM (AP_3v3, N16R8)
- Flash：16MB
- IO擴展晶片：TCA9554PWR (@0x20)
- 工廠韌體：ESP-IDF v5.5.1，I2C掃描到0x24(CH422G)

### 問題
- 螢幕無顯示，背光有亮
- Arduino 韌體（HelloWorld/LVGL）在 PSRAM 初始化時崩潰
- 崩潰發生在 setup() 之前，無任何序列輸出

### 已嘗試
| 組合 | 結果 |
|------|------|
| 工廠韌體 | I2C 當機（掃到0x24而非0x20）|
| HelloWorld (3.3.10, PSRAM=disabled) | 無輸出 |
| HelloWorld (3.3.10, PSRAM=opi) | 編譯錯誤 |
| HelloWorld (3.2.0+pin_config) | 編譯錯誤（pin_config.h 不存在）|
| mini_test (無 GFX/PSRAM) | ✅ 正常輸出序列 |
| simple_i2c (PSRAM=disabled) | 燒錄成功但無輸出 |

### 關鍵發現
- `mini_test` 無 PSRAM 可以正常燒錄和輸出
- 任何涉及 `Arduino_GFX` 的韌體都在 init 時崩潰（PSRAM 相關）
- PSRAM=disabled 仍然會崩潰，可能是 ESP32 在免疫前就嘗試讀取 PSRAM
- GPIO25 可能是 PSRAM 硬體 switch control

### 下一步
1. GPIO25 硬體控制測試（拉低禁用 PSRAM）
2. 考慮使用 ESP-IDF v5.3.1（工廠韌體用同一版本）
