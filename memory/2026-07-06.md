## ESP32 XiaoZhi WiFi Scan 問題（持續）

### 現況
- **症狀**：按「🔍 掃描 WiFi」→ 列表空白，無 SSID 出現
- **已確認正常**：
  - `esp_wifi_scan_start()` ✅ 成功找到 2 個網路（CHT Wi-Fi, IoT）
  - `SetScanDone()` ✅ 有被呼叫（log 確認）
  - `PopulateScanResults()` ❌ 完全沒被執行過（log 從未出現）
  - Watchdog timeout 導致 CPU 0 閒置任務無法執行

### 根本原因（懷疑）
**LvglTask 可能從未成功啟動，或啟動後立即崩潰**

證據：
- `ESP_LOGI(TAG, "LVGL task started")` 在整個 UART log 中**從未出現**
- LvglTask 負責：touch polling + `wifi_scan_done_pending_` check + `PopulateScanResults()`
- LvglTask 如果死了 → `PopulateScanResults()` 不會被呼叫

### 懷疑 LvglTask stack overflow
- 目前 stack：8192 bytes（太小）
- LVGL `lv_task_handler()` + touch indev operations 可能需要更多
- 修復：增加到 **12288 bytes**

### 其他發現
- Watchdog timeout：CPU 0 IDLE0 任務長期無法執行，每 6.5 秒触发一次
- `WifiScanTask` 是獨立的 task（core 1），不受 LvglTask 影響
- 按鈕座標：x=20~460, y=120~200

### 待修（本次）
1. LvglTask stack：8192 → 12288（在 `xTaskCreatePinnedToCore` 呼叫處）
2. 加 `fflush(stdout)` 在所有关键 log 後，確保 UART 及時輸出
3. `ESP_LOGI(TAG, "LVGL task started")` 後加 `fflush(stdout)`

### WiFi 密碼錯誤處理的修復（持續）

#### 問題演變
1. **舊問題**：錯誤密碼 → 沒訊息 → 停留密碼頁
2. **根因**：XiaoZhi 的 WifiStation 自動重連，覆蓋了手動連線意圖
3. **嘗試修復**：
   - `WifiManager::GetInstance().StopStation()` → **當機**（Watchdog timeout）
   - 改用 `esp_wifi_disconnect()` + 3秒延遲 → **當機**
   - 只用 `esp_wifi_set_config()` + `esp_wifi_connect()` → 韌體燒錄但未確認

#### 最新邏輯（16:55 燒錄版本）
```cpp
esp_wifi_disconnect();           // 斷開舊連線
vTaskDelay(pdMS_TO_TICKS(3000)); // 等3秒讓舊IP消失
esp_wifi_set_config();           // 設定新 SSID + 新密碼
esp_wifi_connect();              // 連線
// 輪詢 IP，30秒內沒拿到 IP → "連線逾時"
```
